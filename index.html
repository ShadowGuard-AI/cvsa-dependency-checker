Two Halves, One Report

One run produces a report in two halves. The Safety half runs the safety checker over the project's dependencies in JSON mode, with the global flag when no virtualenv is present, and carries the dependency vulnerability findings. The Pylint half runs pylint over the project and contributes its section. The report also includes a Dependencies section holding the pip freeze output. When the project has a .venv, the freeze and the safety check both run with that venv's own executables, called directly by path with no shell, and they describe the venv environment.

Global Means This Machine

When no virtualenv is present, the safety check describes the environment of this machine, the global environment, and the report says so by its structure: the freeze and the findings belong to the interpreter that ran, not to an isolated project env that does not exist. The project path is resolved to an absolute path before any command runs, so relative and absolute paths behave the same.

Running It, and the Ignore List

Acquisition, exactly as published, with its fault flagged in place: the clone line names ShadowStrikeHQ, git clone https://github.com/ShadowStrikeHQ/cvsa-dependency-checker. That line stands as printed and is flagged, not corrected; the organisation that publishes this repo is ShadowGuard-AI.

The README's usage line names an executable form, ./cvsa-dependency-checker [params]; the code's own form is the one to use, python3 main.py with the project path and the flags below, run from the cloned directory. There is no executable or package by the repo name.

  • --report_file: path to save the report; prints to stdout when not provided.
  • --ignore: comma-separated list of ids to ignore, for example CVE-2023-123,PYLINT:W0613. Report lines in the Safety and Pylint sections that mention an ignored id are removed from the report.
  • -h: show help and exit.

Ran, or Never Ran

An invalid project path exits 1, and a run where the dependency check never ran also exits 1: a report is never dressed up as a result when the check behind it did not happen. One further code path is recorded as inconclusive, in the log's own terms: when zero dependencies are parsed, the program exits 3, a state the README glosses as the dependencies list being empty so nothing could be verified; whether a given project with an empty parse was verified empty or could not be verified cannot be told from the outside, and this page carries exit 3 as inconclusive rather than as an error.

# cvsa-Dependency-Checker
Lists all project dependencies and checks them against the known vulnerabilities databases (e.g., using libraries like `safety`).  Outputs a summary of vulnerabilities, if any, and suggests possible upgrade paths. - Focused on Performs static analysis of source code to identify common security vulnerabilities (e.g., injection flaws, weak cryptography usage) based on pre-defined rules and patterns. Intended for quick, preliminary security assessments during development.

## Install
`git clone https://github.com/ShadowStrikeHQ/cvsa-dependency-checker`

## Usage
`./cvsa-dependency-checker [params]`

## Parameters
- `-h`: Show help message and exit
- `--report_file`: Path to save the report. If not provided, it prints to stdout.
- `--ignore`: Comma-separated list of ids to ignore, for example CVE-2023-123,PYLINT:W0613. Report lines in the Safety and Pylint sections that mention an ignored id are removed from the report.

## Notes

The report includes a Dependencies section holding the pip freeze output. When the project has a .venv, the freeze and the safety check both run with that venv's own executables, called directly by path with no shell, and they describe the venv environment. The project path is resolved to an absolute path before any command runs, so relative and absolute paths behave the same. An invalid project path exits 1, and a run where the dependency check never ran also exits 1.
